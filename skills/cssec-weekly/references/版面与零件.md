# 版面与零件（唯一事实源）

> 本文档集中规定成品 Markdown 的**版面结构**：报刊零件、条目格式（常规简讯 / 一句话短讯 / 赛事条目 / 头条相关文献）、成品命名规范。其他文档（SKILL.md / 写作风格.md / HTML设计.md）引用本文，不再重复表格——**措辞与格式以本文为准**，`scripts/md2html.py` 的零件识别正则与 `scripts/lint.py` 的零件检查与之联动。

## 1. 成品整体结构

```
# CSSEC 周报 第 N 期（YYYY-MM-DD ~ YYYY-MM-DD）
刊号：<dirname>
（导读：2~3 句，编辑部视角）
发刊：YYYY-MM-DD
## 本期主题（头条，1 篇深度报道，篇幅最长）
## 五大板块（按需出现，无料的板块直接省略，绝不硬凑）
  态势感知 / 漏洞情报 / 前沿技术 / 政策法规 / 赛事活动
下期预告：……（可选）
反馈与勘误：……
---
**AI 撰写说明**：……
```

- **标题层级**：期数 H1；板块 H2；条目标题 H3；条目内不再深层嵌套。
- **导读**：2~3 句。首句具体事实钩子，其后允许 1 句编辑部立场（本期为什么把这几件事放一起看）。禁「本周动态频繁/随着……发展」式开门、喊话、第二人称、客套。
- 三格式成品（md/html/pdf）共用人类可读文件名，见 §6。

## 2. 报刊零件（位置与措辞模板）

| 零件 | 位置 | 模板 | 踩线规避 |
|---|---|---|---|
| 期数与日期 | H1 `# CSSEC 周报 第 N 期（YYYY-MM-DD ~ YYYY-MM-DD）` | 标题自带 | 无 |
| 刊号 | H1 下、导读前，单独一行 | `刊号：<dirname>`（如 `刊号：CS26-0801-TP`，值取 `issue_meta.py` 输出 `dirname`） | 无 |
| 本期导读 | H1 下，2~3 句 | 见 §1 导读定义与 `写作风格.md` Part 7.1 | 禁空泛开门、喊话、客套 |
| 发刊电头 | 导读后，单独一行 | `发刊：YYYY-MM-DD` | 无 |
| 下期预告 | 文末（赛事板块之后），1~2 句 | 预告下周可预见的**已知事件**（如「VolgaCTF Final 9 月 17 日开赛」） | **禁**「更多精彩/敬请期待/下期再见」；无已知事件则整件省略 |
| 反馈入口 | 文末最后一行 | `反馈与勘误：[提交 issue](url)`（url 为 GitHub issue 入口） | **禁**「欢迎同学们提出宝贵意见」——只写动作 |
| AI 撰写说明 | 文末最后（反馈入口之后），以 `---` 分隔引出 | 见 §3 | 见 §3 约束 |

## 3. AI 撰写说明

每期成品末尾必须以分隔线 `---` 引出。**Agent 工具名和模型名使用开刊阶段用户确认的名称**。措辞模板：

---

**AI 撰写说明**：本文由 [用户确认的 Agent 工具名] 调用 [用户确认的模型名] 基于安全内参、BleepingComputer、The Hacker News、Krebs on Security、Dark Reading、Schneier on Security、中央网信办、工信部、Hello-CTFtime 等公开权威信息源整理撰写。内容经人工审核，力求准确可靠。

**约束**：

- Agent 工具名和模型名严格使用开刊确认的名称，不得自行更改或编造。
- 信息源列表以**本期实际使用的源**为准（未使用的源不列，lint 会与信息池比对）。
- 文案保持此模板的中性陈述语气，不加「敬请谅解」「欢迎指正」等客套话。
- 不允许 emoji、箭头、直角引号。

## 4. 条目格式

### 4.1 常规简讯（板块主体，每板块 3~6 条）

```
### <标题：动词 + 影响>

<导语：最硬的事实，一句写完。>
<细节/反应：归因、关键数字；素材有真实引语则行内引 1 处。>
<背景或对比（可选）。>

出处：[来源名](url)（多源用「 · 」并列）
```

- 2~4 句、≤3 段；句内归因 ≥1 处（`写作风格.md` 动作 1）。
- **出处行**：`出处：` 后接来源名行内链接；境外源标英文刊名（`· BleepingComputer`），与中文源（`· 安全内参`）并列。

### 4.2 一句话短讯（每板块 3~6 条，置于该板块常规简讯之后）

```
### <标题：动词 + 影响>

<单句事实：主语 + 动词 + 数字/对象，句内自带归因。>

出处：[来源名](url)
```

- 只收录信息密度高、延展性差的条目（版本发布、小额罚款、常规通报、次要 CVE）。
- 与常规简讯的取舍判据见 `写作风格.md` Part 2「分层判据」。
- 格式与常规简讯一致（H3 + 段落 + 出处行），`md2html.py` 无需特殊处理。

### 4.3 赛事条目（信息行式，「赛事活动」板块专用）

「赛事活动」板块每条用结构化信息行（由 `format_events.py` 自动生成，撰写时只润色一句话点睛、删不采纳项）：

```
### <比赛名>[（已延期）]

<一句话点睛：主办/赛制/权重/面向人群等>。

- 竞赛时间：<YYYY-MM-DD ~ YYYY-MM-DD（UTC+8）>（同日起止写单日）
- 链接：[官网](<比赛链接>) · [CTFtime](https://ctftime.org/event/<id>)
```

- **竞赛时间**一律标 `（UTC+8）`（数据源 `Global.json` 本身带 UTC+8；国内赛事默认 UTC+8）。
- **链接**：国际赛事给「官网 + CTFtime」两个行内链接；国内赛事只给 `[官网](…)`。
- 延期赛事标题加「（已延期）」，正文说明新日期未公布。
- 时间/链接用无序列表，不计入正文「叙述优先」的克制——它是结构化信息，属合理用途。

### 4.4 头条相关文献（头条专属）

「本期主题」末尾附一个「相关文献」小节，列出头条正文引用过的**全部出处**（含多源合并的各篇、外部官方博客/公告等），便于溯源。板块简讯不列。

```
### <最后一个头条小节，如「回响」>

（头条正文……）

---

**相关文献**

1. [CSDD 监督委员会辞职，管理层被要求全体卸任](https://…) · BNN
2. [拉脱维亚官员在 120 万人数据泄露后辞职](https://…) · The Record
3. [Hugging Face 事后复盘](https://…) · HF Blog
```

编号列表，每条「标题 + 行内链接 + 来源标注（· 安全内参 / · HF Blog 等）」。分隔线 `---` 与板块分隔一致。

## 5. 其他格式约定

- **链接**：原文以行内 Markdown 链接给出，关键来源附条目末尾出处行；句内归因不塞链接。
- **CVE 等编号**：用行内代码格式 `` `CVE-2026-xxxx` `` 便于检索。
- **配图**：以中性可移植 Markdown 为主；赛事条目可引用 `extra.logo`（比赛标志 URL）。
- **文风与标点**（加粗/引号/破折号配额、引语格式、术语括注）：见 `写作风格.md` Part 1/5，此处不重复。

## 6. 成品命名规范（序列化）

最终成品三格式（md / html / pdf）共用**人类可读文件名**，归档在**自封刊号目录**下：

```
issues/CSYY-MMWW-TP/CSSEC 周报 · 第 N 期.{md,html,pdf}
```

- **目录 = 自封刊号**：仿 CN 刊号形态 `CNXX-XXXX/字母`，前缀换成本组织 `CS`（CSSEC）。`CS` + 2 位年（占 CN 省码位）+ 2 位月 + 2 位「当月第几周」+ 中图分类 `TP`（自动化技术·计算机技术）。2026 年 8 月第 1 周 → `CS26-0801-TP`。全大写、纯英文数字与连接号，字典序 == 时间序，可机读排序。
- **周号 = 本月第几期（顺序号）**：本月已发刊期数 + 1，由 `issue_meta.py` 扫描 issues/ 当月目录计数。发刊偶尔跳周时刊号仍连续（如 8 月第 3 期 = `0803`，即使中间隔了一个未发刊的自然周）；每周一发刊时通常 `01`~`05` 顺排。
- **文件 = 人类可读标题**：`CSSEC 周报 · 第 N 期`，期号**不补零**、不带日期；三格式同 base 不同扩展名。期号由 `issue_meta.py` 扫各目录内成品文件名取最大 +1。
- **来源**：`issue_meta.py` 输出 `dirname`（目录名）与 `filename`（文件名 base）两个字段，二者不同。
- **只影响最终成品**：`sources/` 中间文档（信息池/去重/头条候选/头条素材/事实核对/审稿记录）命名不变。

> **为什么是 `CS`**：CSSEC 的「自封刊号」——形态、分类、号段全按 CN 规范（年份落在国标里 2X 空号位、序号落在报纸号段 0001~0999 而周报正是报纸节奏），唯独前缀是本组织自己封的。对外人是一串正经的刊号，对懂得人是一处会心一笑的梗。
