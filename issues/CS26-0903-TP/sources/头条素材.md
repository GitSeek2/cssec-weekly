## 素材 1 · Hacktron 官方博客（一手，2026-09 披露）

URL: https://www.hacktron.ai/blog/hacking-openai
（项目主页 https://heif-heist.com/ ；thn 转引 2026-09-20）

### 时间线（博客原文标注，均为 2026 年 UTC）

- **7 月 23 日**：审查 Discourse 图片上传管线，发现 HEIC/HEIF 走特殊路径，经 ImageMagick 把 libheif 解析器暴露给攻击者可控文件。
- **7 月 24 日**：用 Opus 4.8 开发出禁用 ASLR 条件下的可行 exploit;开 ASLR 后多轮会话均未成功。
- **7 月 25 日 05:00-06:00**：Claude Opus 5 发布当晚开新会话，约 3 小时产出 ARM64 本地 exploit,随后移植到 x86-64/jemalloc;获得 community.openai.com(Discourse)的 RCE 与管理员权限。
- **08:00-10:00**：经 Bugcrowd 向 OpenAI 提交赏金报告。
- **13:30-15:30**：接管一名 OpenAI 员工账号(其 Codex 连接 GitHub 组织),用其 Codex 在内部 monorepo 开一个无害 PR 作 PoC;15:30 停止全部测试。
- **22:49**：OpenAI 确认修复(报告后约 14 小时)。
- **7 月 26-28 日**：Discourse 周六收到报告、周日回复、周一发布修复并把 ImageMagick 沙箱化，公告 GHSA-vhm9-85gw-x335。
- **9 月 1 日**：OpenAI 支付 6500 美元赏金结案。

### 漏洞链

libheif 堆溢出 → Debian 缺失安全 backport → ImageMagick → Discourse 上传 → OpenAI 公共帮助论坛 → OpenAI SSO 配置缺陷 → 员工 ChatGPT/Codex 账号 → GitHub 连接 → 内部 monorepo。

- **漏洞一(libheif)**:Discourse 通常用 FastImage 处理图片但不支持 HEIF,故交给 ImageMagick,暴露 libheif;`CVE-2026-32882`(CVSS 8.8,NVD: https://nvd.nist.gov/vuln/detail/CVE-2026-32882 )。上游前一年已修复但未标注为安全修复、无 CVE,导致 Debian 12/13 未及时 backport;论坛 Docker 镜像基于 Debian 12,装的是 libheif 1.19.7(修复版 1.22.0 于 2026 年 5 月已发布；截至 9 月 14 日最新安全版为 v1.23.4)。堆溢出发展为 HEIC 解码中的越界读写原语，可发展为 RCE。
- **漏洞二(OpenAI SSO)**:论坛提供 Sign in with OpenAI,与员工内部使用同一 SSO;论坛被接管后可无交互接管活跃用户的 ChatGPT/Codex 账号，进而访问 GitHub、Slack、邮件等连接器。
  博客定性："It is an OpenAI SSO issue that turned the forum compromise into access to ChatGPT and Codex."
  译："把论坛失陷变成 ChatGPT 和 Codex 访问权的，是 OpenAI 的 SSO 问题。"

### 安全边界(做了/没做)

- 做了：仅用一名员工的 Codex 开一个无害 PR 以证明访问权；未阅读敏感信息。
- 没做：未实际访问任何内部代码；随后停止全部进一步测试。

### HEIF Heist 项目

- 多月调查，追踪 libheif 在 Slack、Meta、GitHub Enterprise、Next.js 等的广泛依赖；总计约两个月、token 成本不到 3000 美元、三名研究员；针对每个新公司的 exploit 适配通常只需一两天；覆盖 libheif 1.19.x/1.20.x/1.22.x/1.23.x 多个发布族。
- 检测情况：除 Shopify 外，不知道有其他公司察觉这次活动。

## 素材 2 · thn 报道(英文，2026-09-20)

URL: https://thehackernews.com/2026/09/claude-opus-5-helped-researchers-take.html

- Hacktron 自称"AI 辅助安全研究公司"(AI-assisted security research firm);三名研究员(未具名)。
- libheif 官方与 NVD 记录仅为越界读取，可致崩溃或泄露内存；RCE 是研究者组合内存漏洞后达成的。
- 理论影响面：GitHub、Slack、邮箱等连接器；实际未使用。
- 截至 9 月中，`CVE-2026-32882` 不在美国已知被利用漏洞(KEV)清单；无真实攻击迹象。
- OpenAI 未公开描述登录(SSO)漏洞细节，仅通过修复与付款间接确认。
- Claude Opus 5 于 7 月 24 日晚发布。
- OpenAI 关于赏金的表述："The award recognizes the OpenAI-side finding"(即赏金仅认可 OpenAI 侧发现，论坛不在赏金范围内)。
- 译："这笔赏金认可的是 OpenAI 侧的发现。"
- 能力评注：Opus 5 到 GPT-5.6 Sol "another clear jump"(又一次明显跃升);能力强的 AI 模型正在大幅削减高级攻击所需的时间与技能；Anthropic 此前已报告犯罪及国家背景组织在用 Claude 实施真实入侵。
